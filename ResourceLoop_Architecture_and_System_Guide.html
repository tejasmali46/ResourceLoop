1. Executive Overview & Problem Definition

In modern collegiate and university ecosystems, institutional resources represent millions of dollars in capital expenditure: 4K seminar projectors, acoustic auditorium arrays, robotics testing bays, 3D additive printing labs, precision oscilloscopes, and multi-thousand seat event auditoriums. Yet their governance historically suffers from severe structural failure:

Legacy Campus Bottlenecks
• Fragmented Silos: Departments track resources in disconnected Excel sheets or paper registers.
• Double Booking Collisions: Uncoordinated event approvals result in simultaneous venue conflicts.
• Ghost Bookings & Hoarding: Clubs reserve equipment weeks in advance without returning it on time.
• Untracked Damage & Zero Accountability: Equipment returns damaged with no audit trail of who had custody.
• Lost Approval Chains: Faculty coordinators and HODs receive handwritten letters lost on desks.
The ResourceLoop Solution
• Single Source of Truth: Real-time MongoDB resource ledger with sub-second collision detection.
• Automated Multi-Stage Routing: Student $\rightarrow$ Faculty Coordinator $\rightarrow$ Department HOD $\rightarrow$ Resource Manager.
• Algorithmic Fair Usage: Mathematical monthly quota caps and peak-demand cooling periods.
• Verified Physical Handover: Check-in and return condition reporting with automatic incident generation.
• Immutable Audit Trails: Every role change, decision, check-out, and approval logged with actor ID and timestamp.

3. Role-Based Access Control (RBAC) & Security

ResourceLoop strictly partitions institutional operations across five distinctive persona roles. Permissions are enforced on the backend via authenticate and requireRoles(...) middleware on every API invocation, complemented by frontend <ProtectedRoute> wrappers.

Role Identifier Title & Scope Default Dashboard Core Authorized Powers Strict Restrictions
STUDENT Student / Club Representative /student/dashboard Discover catalog, check eligibility, draft & submit event requests, view own approvals, complete check-out/return. Cannot approve any requests; cannot view other students' private events; cannot self-assign privileged roles.
FACULTY Faculty Coordinator /approvals Review assigned club proposals, verify academic suitability, approve/reject/request changes, forward to HOD. Restricted to assigned clubs/department; cannot bypass operational resource confirmation.
HOD Department Approver (Head of Dept) /hod/dashboard Review high-capacity events ($ge 100$ attendees), departmental budget approvals, schedule conflict arbitration. Cannot approve events belonging to outside departments; cannot modify database users.
RESOURCE_MANAGER Lab In-charge / AV Custodian /manager/dashboard Final operational resource confirmation, handover queue check-out, condition inspection, incident/damage flagging. Cannot override faculty coordinator pedagogical decisions; operational scope only.
ADMIN Institution Administrator /admin/analytics System oversight, provisioning user accounts, assigning roles/departments, audit inspection, system parameters. Safety Rule: Final active administrator account cannot be deactivated or demoted.

Security Architecture Principles

1. Public Registration Role Freezing
When an unauthenticated user submits an account registration via /api/v1/auth/register, the backend hard-overrides the role: role: 'STUDENT' and roles: ['STUDENT']. Any client-sent payload requesting privileged roles is completely disregarded.
2. Insecure Direct Object Reference (IDOR) Shield
Access to GET /api/v1/events/:id validates whether the caller is an Admin, a Resource Manager, the actual event organizer, a member of the organizing club, the assigned Faculty Coordinator, or the Department HOD. Unrelated students receive 403 Forbidden.
3. Account Status Enforcement (Deactivation & Verification)
Accounts with isActive: false or isVerified: false are rejected during login with 403 Forbidden. Furthermore, bearer token verification verifies user status against MongoDB in real time on every API request.
4. Last Active Admin Protection Guarantee
Administrative update endpoints (PUT /api/v1/users/:id) and deactivation endpoints query MongoDB to count remaining active admins. If an admin attempts to deactivate or demote the sole remaining active admin, the server aborts with 400 Bad Request.

4. Multi-Stage Event Approval Workflow Engine

ResourceLoop avoids arbitrary approvals by implementing a deterministic, policy-driven state machine. When an event is submitted, persistent ApprovalTask records are instantiated in MongoDB.

Figure 4.1 — Multi-Stage Deterministic Event Approval Workflow & Branching Conditions

Key Routing Transitions

A Faculty Coordinator Decision
• APPROVED: If requiresHodApproval === true, advances to HOD_REVIEW; HOD task becomes ACTIONABLE.
• CHANGES_REQUESTED: Sets status to CHANGES_REQUESTED, captures changeNotes, and alerts student for revision.
• REJECTED: Sets status to REJECTED, cancels all downstream tasks and releases reservation holds.
B Department HOD Authorization
• Triggered when expectedAttendance >= 100 or the requested venue/equipment has requiresHodApproval: true.
• Validates that reviewer is the official HOD of the event's academic department.
• Upon approval, stage advances to RESOURCE_MANAGER_REVIEW, alerting campus logistics.
C Resource Manager Operational Check
• Final physical verification stage performed by custodial managers.
• Runs atomic capacity collision checks. If all resources are available, status updates to CONFIRMED.
• If an item has reached capacity, request transitions to WAITLISTED.
D Student Resubmission Flow
• Students whose proposal was returned with CHANGES_REQUESTED can update details via POST /api/v1/events/:id/resubmit.
• Re-validates quotas and scheduling conflicts.
• Automatically resets approval stage to FACULTY_REVIEW.

5. Physical Handover, Condition Grading & Incident Lifecycle

Unlike standard booking systems that end at calendar approval, ResourceLoop manages physical custody transfer using serialized QR records, multi-point condition reporting, and automatic incident escalation.

Figure 5.1 — Hardware Custody Transfer, Multi-Point Condition Verification & Incident Escalation

Condition Grades & Automated Maintenance Triggering

Condition Grading Scale
• EXCELLENT: Factory pristine; all cables, adapters, and lenses accounted for.
• GOOD: Standard cosmetic wear, fully functional.
• MINOR_ISSUES: Operable but reported (e.g. slight audio hum, scratch).
• DAMAGED: Broken lens, blown bulb, cracked case. Automatically flags resource as UNDER_MAINTENANCE and halts future bookings.
Incident Resolution Workflow
• Tracked in /incidents with severity (LOW, MEDIUM, HIGH, CRITICAL).
• Assigns responsible parties, repair cost estimates, and investigation notes.
• Upon repair, manager marks incident as RESOLVED, restoring resource to available pool.

6. Scheduling Engine & Fair Allocation Algorithms

The scheduling engine operates directly against active reservations and institutional policy constraints to prevent resource hoarding, conflicting reservations, and unmanageable turnaround times.

Collision Detection & Buffer Intervals

When an event is drafted or submitted, ResourceLoop queries MongoDB for existing reservations overlapping the requested time window $[S_{req}, E_{req}]$, taking into account the required setup buffer $B_{setup}$ and cleanup buffer $B_{clean}$:

Overlap Formula: A conflict occurs if there exists an active reservation with interval $[S_{exist}, E_{exist}]$ such that:
(S_req - B_setup < E_exist + B_clean) && (E_req + B_clean > S_exist - B_setup)
Where reservation status is CONFIRMED or HELD. If capacity is exhausted, the algorithm returns alternative time slots with available inventory.

Algorithmic Fair Usage & Club Quota Management

Monthly Quota Balancing
Each student club is assigned an institutional monthly booking quota (default: 8 high-tier bookings per month). When submitting a new event proposal, the evaluateClubFairUsage service tallies confirmed and active events within the current billing cycle. If the club has exceeded its allowance, the submission is rejected with 429 Too Many Requests unless approved by an Administrator.
Dynamic Waitlist Promotion
When an event is cancelled via POST /api/v1/events/:id/cancel, the system triggers promoteWaitlistedReservations. It scans queued waitlisted requests chronologically and automatically upgrades the earliest eligible waitlisted reservation to CONFIRMED, alerting the student organizer immediately.

Step-by-step event creation wizard with live venue collision checking, equipment multi-selection, expected attendance thresholds, and automatic determination of HOD review requirements.

Comprehensive proposal tracking view featuring visual timeline progress steppers, faculty and HOD review notes, reservation summaries, and inline resubmission forms for returned proposals.

Self-service verification screen for student equipment custody. Displays active checked-out gear, return deadlines, condition records, and digital handover receipts.

Dual-workspace review cockpit. Faculty mode highlights assigned club proposals with syllabus verification; HOD mode highlights high-capacity ($ge 100$) departmental authorizations with 1-click decision modals.

Real-time physical logistics dashboard displaying pending resource confirmations, custody handovers, maintenance alerts, and active venue reservations.
11. Handover Queue & Inspection (/manager/queue)
Fast-paced check-out and return queue with digital condition grading forms (Excellent, Good, Minor Issues, Damaged), custodian signoff, and instant receipt generation.
12. Incident & Damage Registry (/incidents)
Campus-wide equipment maintenance and damage tracking registry with severity categorization, repair cost tracking, and resolution workflow management.
13. User Management & Access Control (/admin/users)
Comprehensive institutional account administrator with live search, role/department filters, account provisioning modal, and the Last Active Admin Safety Rule.
14. Institutional Analytics & Audit Logs (/admin/analytics, /admin/audit)
High-level executive metrics including utilization rates, peak hours, club usage breakdowns, and immutable, filterable audit event trails with actor IP tracking.
